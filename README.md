# Tervasaari PM5 — контроль готовности изоляции

Веб‑приложение для управления, контроля и отчётности о готовности изоляции
трубопроводов на проекте Valmet Tervasaari PM5.

Данные линий взяты из **TESA REGISTER — полный v65.xlsx** (89 линий, 832,5 м, 713,5 м²)
и **ЧЕМОДАНЫ.xlsx** (84 съёмных чемодана на арматуру, 32 линии).

---

## 1. Быстрый запуск (Windows)

1. Установите **Node.js LTS** — https://nodejs.org (один раз, кнопка «LTS», всё по умолчанию).
2. Распакуйте папку `tesa-insulation` куда угодно, например на `C:\TESA`.
3. Двойной щелчок по **`start.bat`**.
4. Откроется браузер: `http://localhost:8080`.

Окно консоли не закрывать — пока оно открыто, работает сервер.
В нём же напечатан адрес для телефонов, например `http://192.168.1.25:8080`.

**Linux / Mac:** `./start.sh` или `node server.js`.

## 2. Телефоны на объекте (Android)

Телефон и компьютер должны быть в **одной Wi-Fi сети** (не мобильный интернет).

**Проще всего — по QR-коду.** После `start.bat` на компьютере сам открывается экран
«Подключить телефон» с большим QR. Наведите камеру телефона → нажмите на всплывшую
ссылку → приложение открылось. Этот экран всегда доступен по адресу
`http://localhost:8080/setup`, его можно распечатать и повесить в бытовке.

**Вручную:** посмотрите адрес в окне консоли — строка «АДРЕС ДЛЯ ТЕЛЕФОНОВ»,
например `http://192.168.8.100:8080`. Тот же адрес пишется в файл
**`АДРЕС ДЛЯ ТЕЛЕФОНА.txt`** рядом с `start.bat` при каждом запуске.

> Адреса вида `169.254.x.x` — служебные, они не работают. Приложение их не показывает.
> Нужен адрес вида `192.168.…`, `10.…` или `172.16–31.…`.

Дальше на телефоне: меню Chrome → **«Добавить на главный экран»** — появится иконка
как у обычного приложения, запуск на весь экран без адресной строки.

### Работа без связи

Приложение при первом входе тихо скачивает в телефон **все 89 линий** (~260 КБ),
поэтому на объекте оно работает целиком, даже когда сервера не видно:

- линии, ветки, цифры, поиск, список и отчёт открываются из памяти телефона;
- отметки готовности сохраняются локально, в шапке появляется
  «нет связи с сервером» и «не отправлено: N»;
- как только связь появляется, всё уходит на сервер само — проверка каждые 45 секунд,
  плюс при возврате в приложение и при подключении к сети;
- принудительно: тап по чипу режима → **«Синхронизировать сейчас»**.
  Там же видно, сколько линий загружено в телефон, и кнопка **«Загрузить все линии»**.

Отметки разных бригадиров не конфликтуют, пока они ведут разные линии.
Если двое правили одну линию, на сервере останется та версия, что пришла последней.

## 2a. Языки интерфейса

Приложение работает на трёх языках: **ENG · EST · RUS**. Кнопки переключения стоят
на экране входа (под названием) и на странице **Дом** — справа над плиткой готовности.

Выбор запоминается в телефоне и держится после перезагрузки, у каждого свой.
При первом запуске язык подбирается по настройкам телефона, иначе русский.
Числа и даты форматируются по языку. Экран `/setup` с QR-кодом тоже трёхъязычный —
кнопки в правом верхнем углу или адрес вида `/setup?lang=en`.

Названия позиций (Release, Materials, Insulation, Cladding, Finishing, Inspection)
одинаковы на всех языках — так их проще обсуждать в смешанной бригаде; поясняющая
подпись переводится.

Номера линий, размеры и данные регистра не переводятся — они одинаковы для всех.

## 3. Вход — доступы и роли

Приложение открывается экраном ввода пароля. **Режим определяется самим паролем** —
имя выбирать не нужно.

| Доступ | Пароль по умолчанию | Что может |
|---|---|---|
| **Manager 1** | `2468` | заполнять и редактировать готовность, вести табель часов, всё смотреть и печатать |
| **Manager 2** | `2469` | то же самое — запасной доступ |
| **Manager 3** | `2470` | то же самое — запасной доступ |
| **Viewer** | `1357` | только смотреть: линии, список, Report, печать и PDF. Табель часов недоступен |

Три доступа Manager нужны, чтобы было видно, **кто именно** внёс изменение: в журнале
пишется имя доступа (Manager 1 / 2 / 3) плюс имя, вписанное в панели режима.

Пароль может быть любой длины (цифры). Для доступа из интернета ставьте **6–8 цифр**.
После 8 неверных попыток вход с этого устройства блокируется на 10 минут.

**Смена паролей и имён.** В облаке — переменные окружения:

| Переменная | Что задаёт |
|---|---|
| `TESA_MANAGER_PIN`, `TESA_MANAGER2_PIN`, `TESA_MANAGER3_PIN` | пароли трёх доступов Manager |
| `TESA_VIEWER_PIN` | пароль наблюдателя |
| `TESA_MANAGER_NAME`, `TESA_MANAGER2_NAME`, `TESA_MANAGER3_NAME` | имена вместо «Manager 1/2/3» |

Локально — файл `data/users.json` (обычный текст), после правки перезапустить сервер:

```json
[
 { "id": "manager",  "name": "Manager 1", "pin": "2468", "role": "manager" },
 { "id": "manager2", "name": "Manager 2", "pin": "2469", "role": "manager" },
 { "id": "manager3", "name": "Manager 3", "pin": "2470", "role": "manager" },
 { "id": "viewer",   "name": "Viewer",    "pin": "1357", "role": "viewer"  }
]
```

Старое имя роли `foreman` понимается как `manager` — файлы и сессии прошлых версий
работают без правок.

Текущий режим показан чипом в правом верхнем углу (розовый — Manager, серый — Viewer).
Нажатие на чип открывает панель: там можно **указать своё имя** (попадёт в журнал
изменений — например «Manager 1 · Иван»), открыть **журнал изменений** и сменить пользователя.

Права проверяются на сервере, а не только в интерфейсе: попытка Viewer'а что‑то
записать возвращает `403`, даже в обход приложения.

## 3a. Журнал изменений — кто и когда

Каждое сохранение пишется в журнал: **дата и время, кто сохранил, что изменилось,
с какого процента на какой**. Отдельно помечаются записи по линиям, по часам и по плану.

Открывается из панели режима (чип в углу) → **«Журнал изменений»**, адрес `#/log`.
Есть выгрузка в CSV и печать. Viewer видит только изменения по линиям —
записи о часах и плане ему не показываются.

## 4. Что умеет

**Дом** — поиск по номеру линии, DN, среде (HMP/HVP/VLA), толщине изоляции,
диаметру. Фильтры: в работе / не начато / готовы 100% / выданы / частичная изоляция.

**Страница линии**
- кнопка **«Открыть чертёж»** — изометрия этой линии в PDF, с номером ревизии;
- короткое название, полный номер, рабочая и расчётная температура;
- размеры **труба / изоляция / металл**, мм — например `219 / 120 / 464`;
- **развёртка металлопокрытия**, мм;
- количество отводов, прямых метров, врезок, конусов, чемоданов;
- общая готовность линии, %;
- **отдельная карточка на каждую ветку** (типоразмер): свои цифры и своя форма
  из 6 позиций с чек‑боксами;
- примечание по линии;
- линии, с которыми соединяется (переход в один тап);
- состав по регистру (все элементы с размерами);
- кнопки: Домой · Список · Report · Печать линии.

**Список** — полная таблица линий (сортировка по любому столбцу, экспорт CSV).

**Report** — готовность в % по **м²** и **погонным метрам**: по проекту, по каждой
из 5 позиций и по каждой линии; сколько линий выдано под изоляцию, сколько
изолировано и покрыто металлом. Кнопки **PDF / Печать**, **Поделиться**, **CSV**,
**Резервная копия**.

## 5. Как считается готовность (модель v2)

### Ветки линии

На одной линии обычно **несколько типоразмеров трубы** (веток) — например
`219/120/464`, `114/100/332`. Размеры пишутся как **труба / изоляция / металл**, в мм.
У каждой ветки своя форма и свои объёмы: изоляция DN200 и DN15 — разная работа.

### Позиции и веса

| Позиция | Вес | Как отмечается |
|---|---|---|
| 1. Материалы на месте | 5% | поле ввода % (или кнопки 50 / 100 / 0) |
| 2. Изоляция (вата) | 30% | сколько метров заизолировано + чек‑боксы по отводам |
| 3. Металлопокрытие | 40% | метры + отводы + чек‑боксы по чемоданам |
| 4. Отделка | 23% | поле ввода % |
| 5. Приёмка | 2% | 50% / 100% |

Чемоданы (съёмные короба на арматуру) входят в позицию «Металлопокрытие» —
отдельными чек‑боксами с номерами по проекту.

### Трудоёмкость: чем считается «сделано»

Внутри позиции проценты считаются не на глаз, а по объёму работ:

- **отвод = 1,5 м** прямой трубы;
- **чемодан = 1,5 часа**, переведённые в метровый эквивалент этой ветки
  (на DN250 это ≈ 6 м трубы, на DN25 ≈ 9,5 м — маленький чемодан «стоит» дороже);
- **производительность по диаметру**: на м² тонкие трубы дороже по времени —
  коэффициент 1,8 для DN ≤ 50, 1,25 для DN 65–150 и 1,0 для DN ≥ 200.

Отсюда считаются **нормо-часы** каждой ветки и линии. Доля ветки в линии и доля
линии в проекте — по этим нормо-часам, а не по «голым» метрам.

Нормы откалиброваны так, что весь проект даёт **1249 нормо-часов** — ровно бюджет
из табеля. Поэтому «готовность по часам» в Report прямо сравнима с потраченными часами.

```
готовность ветки = 5%·Материалы + 30%·Вата + 40%·Металл + 23%·Отделка + 2%·Приёмка

  вата ветки   = (метры + 1,5 × отводы) / (все метры + 1,5 × все отводы)
  металл ветки = (метры + 1,5 × отводы + чемоданы × экв.) / (то же по всей ветке)

готовность линии   = сумма веток, взвешенная по нормо-часам
готовность проекта = взвешенно по нормо-часам (плюс справочно по м² и по п.м.)
```

**Переход с прежней модели.** Старые отметки (ступени 5/25/75/100) не переносятся:
при первом запуске новой версии они очищаются, готовность вносится заново по факту.
Это разовая операция, она пишется в журнал.

## 5a. Чертежи

В комплекте лежат все **89 изометрий** (папка `public/drawings`, 14 МБ). На странице
каждой линии есть кнопка **«Открыть чертёж»** — PDF открывается в отдельной вкладке,
на телефоне листается и увеличивается пальцами.

Открытый однажды чертёж остаётся в памяти телефона и потом открывается **без связи**.
Чтобы скачать все сразу (перед выходом на объект): чип режима → **«Загрузить чертежи»**,
это 14 МБ по Wi-Fi.

**Как обновить чертежи.** Положите новые PDF в `public/drawings` вместо старых
и пересоберите регистр: `python tools/extract.py`. Имя файла должно начинаться
с номера линии, ревизия — суффиксом `_R1`, например
`50157-HMP-200-16C1B_R1.pdf`. Приложение само подхватит номер и ревизию.

## 6. Данные и резервные копии

Всё лежит в папке `data/`:

| Файл | Что это |
|---|---|
| `seed.json` | регистр линий (только чтение, из v65) |
| `state.json` | отметки готовности и примечания |
| `users.json` | пользователи и PIN |
| `history.json` | журнал изменений (кто, когда, с какого на какой %) |
| `sessions.json` | активные входы |

Отметки, сделанные в версиях до 1.4 (без веток), переносятся автоматически при
первом открытии линии: значение позиции применяется ко всем веткам, бывшая
подпозиция «отделка» становится позицией Finishing.

Резервная копия — кнопка **«Резервная копия»** в Report (скачивает JSON).
Восстановление — `POST /api/import` тем же файлом, или просто положить
`state.json` обратно в `data/` и перезапустить.

**Обновление регистра.** Когда появится v65/v66 — пересоберите `seed.json`
скриптом `tools/extract.py` (лежит рядом, поправьте путь к xlsx вверху файла)
и положите новый `seed.json` в `data/`. Отметки готовности в `state.json`
привязаны к номеру линии (50150, 50151 …) и не потеряются.

## 7. Доступ из любой сети — размещение в облаке

Если компьютер стоит в конторе, а отмечать надо на объекте, приложение
размещается в облаке. Есть два варианта хранения данных.

### Вариант А — данные в вашем Google Drive (без ежемесячной платы)

Все отметки лежат файлом `state.json` в папке **«Tervasaari PM5 — данные»**
вашего «Моего диска». Приложение читает его при старте и переписывает при каждом
сохранении. Само приложение при этом крутится на **бесплатном** плане Render:
его диск не нужен, данные не на нём.

| Переменная окружения | Значение |
|---|---|
| `TESA_STORE` | `drive` |
| `TESA_GOOGLE_CLIENT_ID` | из Google Cloud |
| `TESA_GOOGLE_CLIENT_SECRET` | из Google Cloud |
| `TESA_GOOGLE_REFRESH_TOKEN` | выдаёт `node tools/google-auth.js` |
| `TESA_DRIVE_FOLDER` | необязательно, имя папки на диске |
| `TESA_FOREMAN_PIN`, `TESA_VIEWER_PIN` | пароли, 6–8 цифр |

Порядок: `node tools/google-auth.js` на своём компьютере — он откроет браузер,
попросит разрешение и напечатает готовые строки. Проверка связи:
`node tools/test-drive.js` (или `--mock`, чтобы проверить сам код без Google).

**Обязательно** переведите экран согласия в Google Cloud из «Testing» в
«In production» — иначе Google обнуляет доступ каждые 7 дней и приложение встаёт.
Приложение просит только область `drive.file`: оно видит исключительно
те файлы, которые само создало, ко всему остальному на вашем диске доступа нет.

Что происходит, если Google на минуту недоступен: приложение отвечает пользователю
сразу, а запись повторяет — 4 быстрые попытки, затем раз в 30 секунд, пока не пройдёт.
Параллельно кладёт локальную копию, и при следующем запуске поднимает более свежую
из двух. Состояние видно в приложении: чип режима → строка «Хранилище», и по
адресу `/api/health`.

Минус бесплатного плана: сервис засыпает после 15 минут простоя, первое открытие
после паузы занимает около минуты. Данные при этом целы.

Пошаговая инструкция — **«Tervasaari PM5 — база на Google Drive.pdf»**.

### Вариант Б — платный план Render с диском

≈7 $/мес + 1 ГБ диска. Ничего настраивать в Google не надо, засыпания нет.
`TESA_DATA=/var/data`, диск смонтирован туда. Инструкция —
**«Tervasaari PM5 — размещение в облаке.pdf»**.

### Вариант В — без облака

**Cloudflare Tunnel:** компьютер в конторе остаётся сервером, но получает внешнюю
ссылку: `cloudflared tunnel --url http://localhost:8080`.

Либо просто офлайн-режим (раздел 2): отмечаете на объекте без связи, вечером
в конторе телефон отправляет всё сам.

Если сервер живёт на ПК, полезно положить папку `data` внутрь синхронизируемой
папки Google Drive — отметки будут уезжать в облако с историей версий. Удалённого
доступа это не даёт, но от потери данных страхует.
